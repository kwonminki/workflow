# 에이전트 작업 규약

## 역할

사용자는 기술 총괄과 목표·판단을 논의합니다. 총괄은 실행 담당에게 작은 범위의 목표와 입력 버전, 성공 조건, 수정 가능한 파일/출력 경계를 전달합니다. 기록 담당은 총괄이 수락한 결과를 설명 문서와 작업 상태에 연결합니다. 한 에이전트가 여러 역할을 수행해도 기록의 책임 범위는 구분합니다.

등록에는 역할 이름과 실제 오케스트레이터의 session ID를 사용합니다. `apply agent`는 이 값을 저장할 뿐 해당 세션을 생성하거나 활성 상태를 확인하지 않습니다. 세션이 바뀌면 새 값을 등록하고 과거 답변의 작성 스냅샷은 보존합니다.

## 시작과 재개

1. 지정한 프로젝트 workspace에서 `inbox --require-clear`를 실행합니다.
2. 질문의 문서 버전·인용문·앞뒤 문맥·기존 답변·후속 의견을 함께 읽습니다.
3. 할 수 있는 승인된 변경을 수행합니다. 적용 후 같은 사용자 message ID에 `applied`와 실제 근거를 답합니다.
4. 나중에 할 일은 목표·다음 행동·의존 관계·역할을 갖춘 노드를 먼저 만들고 `deferred`로 연결합니다.
5. 질문이 해결되지 않았으면 `seen`으로 판단을 남길 수 있지만 inbox에서 제거되지 않습니다. 응답이 없다는 이유로 사용자가 승인했다고 추정하지 않습니다.

## 실행과 결과

`run`은 로컬 명령의 argv를 셸 없이 실행합니다. 사용자의 실제 작업 권한을 넓히는 기능이 아닙니다. 실행 전 등록한 node/agent와 workspace가 맞는지 확인합니다. 명령 인자에 비밀을 넣지 않습니다. 결과는 실행 기록과 별도로 판단합니다.

보고 문서에는 다음 순서를 권장합니다.

- 무엇을 확인하려는가: 목표, 입력/비교 기준과 버전
- 무엇을 실행했는가: run ID, 명령/cwd, 코드 commit, 환경 정보를 별도 근거에 연결
- 무엇이 나왔는가: 수량, 지표 의미와 분모, 실제 출력, 실패/미측정 범위
- 어떤 판단을 했는가: 관찰과 추정 구분, 결정 이유와 근거
- 무엇을 할 것인가: 자동으로 진행할 항목, 의존 조건, 사용자에게 필요한 질문

`run` 기본 기록은 전체 환경·코드 commit·모델 파일 hash를 자동 수집하지 않습니다. 재현에 필요한 manifest를 생산자가 따로 만들고 결과에 연결합니다. 설명 문서는 날짜가 있는 최신 내용을 위에 추가하며, 원문을 고칠 때는 사용자 코멘트의 정확한 의미를 보존합니다.

## 완료와 인계

exit 0은 명령 성공입니다. 일부 완료에서 완료로 바꾸려면 명시한 완료 조건을 충족했고, 남은 범위가 다른 노드에 있으며, 검증 근거를 실제로 확인했는지 점검합니다. `done`은 완료 이유+근거 필드가 필수지만 저장 도구가 근거 내용을 인증하지는 않습니다.

이전 담당에게 재전달할 때 노드 ID, 문서/인용 revision, thread/message ID, 작성 role/session, run ID, 실제 결과 위치와 다음 행동을 전달합니다. 이 코어는 전달을 자동 수행하지 않습니다. 실제 메시지 전달/수신/재개 결과는 총괄이 결과 문서 또는 run 사후 기록에 남깁니다. 죽은 세션을 재개했다고 표시하지 않고 새 담당에게 인계합니다.

사용자 답변 알림의 읽음은 사용자가 웹에서 처리합니다. 에이전트의 inbox 처리가 사용자 읽음 상태를 바꾸지 않습니다.
