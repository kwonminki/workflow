# 외부 서비스와 오케스트레이터 확장

현재 Notion/Linear/오케스트레이터 API 연동은 구현하지 않았습니다. 이 문서는 도입 시 적용할 경계이며 자동 동기화 기능의 사용 설명이 아닙니다.

## 데이터의 담당 위치

| 위치 | 권장 역할 | 이 코어와 연결하는 방법 |
| --- | --- | --- |
| 웹 | 구체 실행, 입출력, 근거, 문맥 있는 질문·답변 | 현재 코어 |
| Notion 등 문서 서비스 | 큰 설계, 합의, 장기 문서 | 작업 links/evidence에 실제 문서 URL 연결 |
| Linear 등 이슈 서비스 | 팀의 업무 범위, 우선순위, 사람 담당 | links에 실제 이슈 URL 연결 |
| 오케스트레이터 | 세션 생성/재개, 작업 전달, 실제 실행 상태 | agents에 정확 role/session 등록, 전달 결과는 별도 기록 |

하나의 필드를 양쪽에서 자유롭게 편집하고 무조건 덮어쓰는 동기화는 피합니다. 예를 들어 사람 담당자는 이슈 서비스가, 실행 근거는 웹 기록이 소유하도록 명시합니다. 웹의 `owner`는 로컬 agent ID이며 외부 계정 ID가 아닙니다.

## 커넥터를 추가할 때

1. 승인된 정확 대상만 연결하고 비밀 값은 프로세스 환경/비밀 저장소에서 읽습니다. 공개 예제에는 placeholder만 둡니다.
2. 쓰기 전에 최신 외부 revision과 사용자 변경을 읽고 local revision과 비교합니다.
3. 기존 문서 전체 교체보다 날짜가 있는 업데이트를 앞에 추가하고, 원문/댓글을 보존합니다.
4. 원격 결과를 재조회하여 예상 반영을 확인하고 source/target ID·revision·시각·성공/실패·실제 URL의 동기화 영수증을 남깁니다.
5. 읽음/사용자 답변과 계획 완료/훈련 승인 등을 자동으로 같은 상태로 매핑하지 않습니다.
6. 재시도에는 idempotency key를 사용하고, 실패는 미반영으로 남깁니다. 어댑터 실행만으로 자동 동기화를 제공한다고 선언하지 않습니다.

## 에이전트 라우팅 확장

thread owner는 생성 당시 담당을 보존하는 참고 필드입니다. 담당 변경 시 현재 node.owner와 과거 message.author를 함께 읽고 실제 살아 있는 세션을 확인합니다. 기존 세션에 전달했는지, 수신했는지, 작업을 시작했는지, 검증했는지를 분리해 기록하는 전달 원장을 확장할 수 있습니다.

안전한 다음 확장 후보는 실제 전달 영수증, 문서 Markdown 렌더러, 샘플/미디어의 allowlist 게시, 그래프 그룹 접기, 프로젝트별 권한·인증과 DB 저장입니다. 필요한 기능만 실제 테스트와 함께 추가하고 README의 제공 범위를 갱신합니다.
